# Submission readiness checklist

This checklist separates repository evidence from items the group must produce and verify before the
SE3090 submission. It intentionally does not claim evidence that is not committed or independently
reproducible.

## Verified technical evidence

- [x] ASP.NET Core API is deployed.
- [x] Render `/health` returns `Healthy`.
- [x] Render Swagger is reachable at `/swagger/index.html`.
- [x] React is deployed at `https://se3090.vercel.app/`.
- [x] Vercel application routes support direct navigation and refresh through `frontend/vercel.json`.
- [x] React production build passes.
- [x] React tests pass locally.
- [x] Flutter source, tests and CI build configuration are committed.
- [x] Flutter tests and analyzer pass locally.
- [x] JWT authentication, role authorization and approval restrictions were exercised against the live API.
- [x] Agentic AI workflow code includes distinct agents, allow-listed tools, persisted state, validation and approval.

## Must be verified or retained for submission

- [ ] Run backend integration tests with the intended PostgreSQL connection and retain the passing CI result.
- [x] Run `perf/smoke.js` and save the k6 summary, environment, provider and thresholds in the performance report.
- [x] Fix the AI workflow failure/error-rate measurement and rerun k6.
- [ ] Reduce deployed ticket-list and dashboard p95 below the assignment thresholds, then rerun k6.
- [ ] Download and test the CI-produced Flutter APK on an Android device or emulator.
- [ ] Record PostgreSQL hosting, migration and restricted-credential evidence.
- [ ] Demonstrate the Flutter → API → PostgreSQL → Agentic AI → React approval → Flutter update workflow.
- [ ] Keep the repository, deployed services and video accessible until the specification's required date.

## Group report deliverables

- [ ] One consolidated PDF containing the group report and all individual sections.
- [ ] Architecture, database/ER, API, React, Flutter and Agentic AI sections.
- [ ] Testing, agent evaluation, performance and deployment reports.
- [ ] ADRs and references.
- [ ] Demonstration video link with access tested in a private/incognito window.

## Individual process evidence

Each student must add their own material; these are not generated by the repository code:

- [ ] Contribution statement and owned component.
- [ ] Meaningful commit, branch, issue, pull-request and review evidence.
- [ ] Test evidence and a challenge/learning summary.
- [ ] AI usage log containing date, tool/model, task, accepted/rejected output and verification.
- [ ] Approximately one-page AI reflection and signed declaration.

The assignment explicitly rejects fabricated commit history, invented test results and reflections that do not
match the student's real work and understanding.
